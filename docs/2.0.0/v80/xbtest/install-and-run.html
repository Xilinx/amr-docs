How-to install and run a pre-built Xbtest design on an ALVEO V80 card¶

Note: For xbtest we have to revert to AVED design as xbtest with AMR design not supported in this release. Below are the instructions to install AMI and xbtest with prebuilt xbtest design images.

Before You Begin¶

Dependencies¶

Supported OS and kernel. See Supported Kernels and Distributions

Note: root/sudo permissions are required.

Tools

  • Vivado™ 2025.2

Preparing for Xbtest Installation¶

  1. Confirm the server is running a supported OS. Follow the instructions provided in the Alveo V80 Data Center Accelerator Cards Installation Guide (UG1617) to physically install the card in your server.

  2. Get the latest Xbtest installation package for your Alveo card.

    1. For the most recent version of the example design, refer to Release Notes.

      • xbtest Deployment Archive is a .zip of the xbtest installation package. It is pre-built from the xbtest source code, using the Vivado™ tools version noted in the Release Notes

    2. Download the latest xbtest Deployment Archive to the server that contains your Alveo card.

    3. Unzip the archive.

    4. Unlike prior Alveo platforms, AVED does not use the Xilinx RunTime Library (XRT). Instead, AVED includes the AVED Management Interface (AMI) as part of the example design. Before AVED installation, ensure that XRT has been removed. It’s not possible to have AMI and XRT running on the same host at the same time.

    Ubuntu:

    # Check if XRT is installed
apt list | grep xrt

# Remove XRT if present
sudo apt remove xrt

    RHEL:

    # Check if XRT is installed
yum list | grep xrt

# Remove XRT if present
sudo yum remove xrt

Xbtest installation with an existing AMR¶

Follow the steps below to install AVED/xbtest fw/sw with existing AMR installation

  • Ensure the existing AMR environment is functional

  • AMI and AMC versions are compatible (matched)

  • AMC is in READY state before proceeding

  • Unzip the the xbtest installation package that was downloaded from latest release as mentioned in above section.

  • Program the OSPI fpt image(flash_setup/fpt_setup_amd_v80_gen5x8_25.1_exdes_1_yyymmdd.pdi) using the ami_tool cfgmem_fpt command or through jatg mentioned below.

  • using the ami_tool cfgmem_fpt:

    cd amd_v80_gen5x8_25.1_xbtest_stress_20251113 (this is just an example release package, make sure to replace this with latest) sudo ami_tool cfgmem_fpt -d <B:D.F> -i <flash_setup/fpt_setup_amd_v80_gen5x8_25.1_exdes_1_yyymmdd.pdi> -p 0 -t primary

  • Using vivado HW Manager and Jtag:

    update the Flash Partition Table (FPT) image in flash using Vivado HW Manager and JTAG. Refer to Updating FPT Image in Flash for step-by-step instructions. If successful, Vivado HW Manager will report this with a pop-up message: “Flash programming completed successfully.” Cold boot the server to boot from flash.

AVED Installation¶

Installing AVED is a two-step process. First, you will install the pre-built AVED package onto the host. Second, you will program AVED into flash on your Alveo card.

To install the package onto the host, navigate to the directory with the aved_install.sh script, and execute this script.

   $ sudo ./aved_install.sh

AMR installation with existing AVED/xbtest¶

Follow the steps below to install AMR fw/sw with existing AVED/xbtest

  • Ensure the existing AVED / xbtest environment is functional

  • AMI and AMC versions are compatible (matched)

  • AMC is in READY state before proceeding

  • Build the AMR sources [Rebuild] (../../getting-started/rebuild.md)

  • Program the AMR OSPI fpt image using the ami_tool cfgmem_fpt command

       sudo ami_tool cfgmem_fpt -d <BDF> -i <amr_ospi_fpt.bin> -t primary

Install the AMR software packages¶

To install the package onto the host, navigate to the directory with the debian or rpm packages depending on your host OS. Install libami*, amitool*, ami* packages

    1. Installing debian packages:
        sudo dpkg -i libami_x.x.x.xxx.xxx_amd64.deb
        sudo dpkg -i ami_x.x.x.xxx.xxx_amd64.deb
        sudo dpkg -i amitool_x.x.x.xxx.xxx_amd64.deb

    2. Installing rpm pakcages:
        sudo rpm -ivh libami_x.x.x.xxx.xxx_amd64.rpm
        sudo rpm -ivh ami_x.x.x.xxx.xxx_amd64.deb
        sudo rpm -ivh amitool_x.x.x.xxx.xxx_amd64.deb

Testing xbtest¶

Two sets of tools are provided to test the xbtest design running in hardware: a suite of AMI commands (ami_tool <command>) and xbtest testcases (xbtest -d <Bus:Device.Function(BDF)> -c <testcase>). A subset of these tools are illustrated below.

ami_tool Overview¶

The overview command shows basic information including the AMI version, the BDF, the device name, the currently programmed design’s UUID, and the device state. Take note of the BDF of your card (21:00.0 in the example below), which will be used in subsequent commands.

AMI¶

Version | 2.0.0 (0) Branch Hash | 15a98eb71fdee61c662ff155227c0525dc3cbbd7 Hash Date | 20260317 Driver Version | 2.0.0 (0)

BDF | Device | Serial Number | UUID | AMC | State¶

21:00.0 | ALVEO V80 INT | XFL1GF4VJ1KW | 00000000000000000000000032314bde | 2.0.0 (0) | READY

If the device state is NOT_READY, cold reboot the system.

Confirm the AMI driver version matches the AMC version on the device before continuing (compatibility is indicated by having the same Major & Minor version numbers in the AMI/AMC Major.Minor.Patch version number format). If they do not match, AMI behavior is undefined.

The mfg_info command displays the card manufacturing information stored on an EEPROM. The values will vary from card to card.

ami_tool sensors¶

The sensors command displays the available sensors and their values. The values may vary. For removable sensors (such as QSFP devices), the Status may appear as “invalid”; this indicates that no device is inserted. The * displayed after a sensor status indicates that the value retrieved was from a cached store - i.e., the value had been previously updated within the refresh timeframe (1 second).

Troubleshooting¶

For debugging information, see AMR Debug Techniques.

Next Steps¶

This getting started guide covered AMR installation and basic hardware testing commands. If you would like to explore the full set of hardware test commands available, see:

  • AMR Management Interface userguide

  • xbtest User Guide / Usage / command line options

Notably, some interesting commands to try are:

  • the AMI cfgmem_program command, which updates the PDI in flash over the PCIe interface. See AMR Updating Design PDI in Flash

  • additional pre-canned xbtest tests are available to test other features on the card. Please refer to xbtest User Guide / Pre-canned tests section. The available pre-canned tests are: gtm_prbs, gtyp_prbs, memory, mmio, power, stress, and verify.
