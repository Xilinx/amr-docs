# How-to install and run a pre-built AMR design on an ALVEO V80 card

This is a getting started guide for the Adaptive Management Runtime (AMR) to be used with the provided pre-built AMR package file. This guide offers instruction in installing the package on your server and running key commands to test and evaluate the design example. The pre-built example image includes the AMR base design. This provides a turnkey card capable of running through the canned tests in the xbtest suite. For the AMR source files, only the AMR base design is included - the xbtest IP is not included and instead would be replaced with a user application.

### Preparing for AMR Installation

1.  Confirm the server is running a supported OS. Follow the instructions provided in the *Alveo V80 Data Center Accelerator Cards Installation Guide* ([UG1617](https://docs.amd.com/go/en-US/ug1617-alveo-v80)) to physically install the card in your server.

2.  Get the latest AMR installation package for your Alveo card.
    
    1.  For the most recent version of the example design, refer to [AMR Release Notes](../../release-notes.md).
        
        -  *xbtest Deployment Archive* is a `.zip` of the AMR installation package. It is pre-built from the xbtest source code, using the Vivado™ tools version noted in the [AMR Release Notes](../../release-notes.md)
    
    2.  Download the latest *xbtest Deployment Archive* to the server that contains your Alveo card.
    
    3.  Unzip the archive, and find the `design.pdi` (which will be used in the xbtest installation). Review [AMR Installing the Design onto the Card](../../deployment/install-card.md) for details on deployment package usage and programming flow.

3.  Unlike prior Alveo platforms, AMR does not use the Xilinx RunTime Library (XRT). Instead, AMR includes the AMR Management Interface (AMI) as part of the example design. Before AMR installation, ensure that XRT has been removed. It’s not possible to have AMI and XRT running on the same host at the same time.

    **Ubuntu:**

    ```bash
    # Check if XRT is installed
    apt list | grep xrt

    # Remove XRT if present
    sudo apt remove xrt
    ```

    **RHEL:**

    ```bash
    # Check if XRT is installed
    yum list | grep xrt

    # Remove XRT if present
    sudo yum remove xrt
    ```

## AMR Installation

Installing AMR is a two-step process. First, you will install the pre-built AMR package onto the host or you can rebuild the AMR sw packages as mentioned in [Rebuild](../../getting-started/rebuild.md). Second, you will program xbtest into flash on your Alveo card.

To install the package onto the host, navigate to the directory with the debian or rpm packages depending on your host OS. Install libami*, amitool*, ami* packages

    1. Installing debian packages:
        sudo dpkg -i libami_x.x.x.xxx.xxx_amd64.deb
        sudo dpkg -i ami_x.x.x.xxx.xxx_amd64.deb
        sudo dpkg -i amitool_x.x.x.xxx.xxx_amd64.deb

    2. Installing rpm pakcages:
        sudo rpm -ivh libami_x.x.x.xxx.xxx_amd64.rpm
        sudo rpm -ivh ami_x.x.x.xxx.xxx_amd64.deb
        sudo rpm -ivh amitool_x.x.x.xxx.xxx_amd64.deb

Note: Install libami* package before amitool* and ami* packages.


To program AMR onto your Alveo card for the first time, update the Flash Partition Table (FPT) image in flash using Vivado HW Manager and JTAG. Refer to [AMR Updating FPT Image in Flash](../../deployment/update-fpt.md) for step-by-step instructions. If successful, Vivado HW Manager will report this with a pop-up message: “Flash programming completed successfully.” Cold boot the server to boot AMR from flash.

## Testing AMR

Two sets of tools are provided to test the AMR design running in hardware: a suite of AMI commands (`ami_tool <command>`) and xbtest testcases (`xbtest -d <Bus:Device.Function(BDF)> -c <testcase>`). A subset of these tools are illustrated below.

<span id="how-toinstallandrunapre-builtamrdesignonanalveocard-ami-tooloverview"></span>

### ami\_tool Overview

The overview command shows basic information including the AMI version, the BDF, the device name, the currently programmed design’s UUID, and the device state. Take note of the BDF of your card (**21:00.0** in the example below), which will be used in subsequent commands.

Branch
Hash           | 15a98eb71fdee61c662ff155227c0525dc3cbbd7
Hash Date      | 20260317
Driver Version | 2.0.0  (0)


BDF     | Device        | Serial Number | UUID                             | AMC        | State
-----------------------------------------------------------------------------------------------
21:00.0 | ALVEO V80 INT | XFL1GF4VJ1KW  | 00000000000000000000000032314bde | 2.0.0  (0) | READY

If the device state is NOT\_READY, cold reboot the system.

Confirm the AMI driver version matches the AMC version on the device before continuing (compatibility is indicated by having the same Major & Minor version numbers in the AMI/AMC Major.Minor.Patch version number format). If they do not match, AMI behavior is undefined.

## Next Steps

This getting started guide covered AMR installation and basic hardware testing commands. If you would like to explore the full set of hardware test commands available, see:

  - [AMR Management Interface userguide](../../deployment/ami-tool-guide.md)

  - [xbtest User Guide / Usage / command line options](./user-guide/source/docs/usage/command-line-options.html)

Notably, some interesting commands to try are:

  - the AMI cfgmem\_program command, which updates the PDI in flash over the PCIe interface. See [AMR Updating Design PDI in Flash](../../deployment/update-pdi.md)

  - additional pre-canned xbtest tests are available to test other features on the card. Please refer to [xbtest User Guide / Pre-canned tests section](./user-guide/source/docs/pre-canned-tests/pre-canned-tests-description.html). The available pre-canned tests are: gtm\_prbs, gtyp\_prbs, memory, mmio, power, stress, and verify.

For a quick look at how to build AMR, refer to the getting started guide: [How-to Rebuild an AMR Design for Yourself](../../getting-started/rebuild.md).
